## 관찰

`codex/catalog-contract`, `codex/manual-meal`, `codex/session-integrity`는 Git
조상관계상 기준 브랜치에 없었다. 그러나 `git cherry`는 각 substantive patch를
`-`로 표시했다. 같은 변경이 기준 브랜치에 새 해시로 이미 들어갔다는 뜻이다.

- catalog contract `f249b44`와 `ae64d01`은 기준의 `3db39d1`과 `2d247b9`에
  patch-equivalent였다.
- manual meal `eec4c3b`는 기준의 `750f674`에 patch-equivalent였다.
- session integrity `6cbfaae`는 기준의 `4e511a4`에 patch-equivalent였다.
- 기준 브랜치의 dual-write 로그는 새 구현 해시를 이미 인용했다.

정상 3-way merge는 오래된 DB migration, 카탈로그 계약, Boot/CoachCard, locale,
troubleshooting 로그와 현재 hardening을 다시 충돌시킨다. 옛 브랜치 내용을
선택하면 현재 tree를 회귀시킬 수 있으므로 substantive patch와 옛 로그를
재적용하지 않았다.

## 적용

Social 계약과 Phase 0 결정 기록을 먼저 fast-forward한 뒤, 현재 tree를 보존하는
`ours` strategy로 세 ancestry를 순서대로 기록했다.

```text
cdc8cc766b80bff60aa47b4e4e1b583b37b337ce merge(coach): record integrated session ancestry
993f67aa98622cd698f7137d6dcfe723b8075587 merge(food): record integrated manual meal ancestry
da021344e1cce79ec7283cd0214971272fe48638 merge(catalog): record superseded contract ancestry
```

세 merge의 tree hash는 모두 다음 값으로 같았다.

```text
276f55f366dc09c7724b8e91b155190e89e46563
276f55f366dc09c7724b8e91b155190e89e46563
276f55f366dc09c7724b8e91b155190e89e46563
```

각 merge 뒤 `git diff --exit-code HEAD^1 HEAD`는 exit 0이었다. 최종
`merge-base --is-ancestor`는 catalog contract/client/data/worker, manual meal,
session integrity, Social contract/system design, Phase 0 gate 모두 `yes`를
반환했다. 이 검증은 history와 tree 동일성만 말한다.

## 경계와 되돌림

미추적 `node_modules`는 어떤 merge에도 포함하지 않았고 기존 worktree를 삭제하지
않았다. 이 단위는 dependency, feature code, migration, deployment, TestFlight,
App Store 상태를 바꾸지 않는다. ancestry 기록이 잘못됐다면 세 merge commit을
reverse order로 revert하지 말고, 공유 전 통합 브랜치를 해당 merge 전 커밋으로
대체하는 별도 승인된 Git 작업이 필요하다. 이미 공유된 뒤에는 후속 정정 기록으로
처리한다.

Function 검증은 Git ancestry와 clean worktree 확인까지다. Quality 검증은 모든
merge가 동일 tree를 유지한 것까지다. 앱 테스트와 Product/workflow 검증은 이
history-only 단위 자체로 새로 실행하지 않았다.
