## 무엇

"검증 가능한 순수 코어 먼저" 기조 그대로, 기기 없이 jest로 검증되는 두 모듈:

**`classifyEvent`** — JUICE 엔진의 두뇌. 로깅 이벤트를 받아 연출 티어를 판정한다(렌더는 별개 — Skia/Reanimated 레이어가 verdict를 실제 이펙트로 변환). **순수·동기·never throws** = 로깅 비차단 계약(§6.4)의 판정부.

- PR / 하드셋(RIR 0) → **T3 (OVERDRIVE 진입)**, 견고한 세트(목표 reps + RIR 1–3) → **T2**, 그 외 기록된 세트 → **T1**.
- 세션완료/연속 마일스톤/레벨업 → **T4**.
- `reason`은 DB `PowerEvent.reason` enum(set|pr|session|streak|levelup)에 정확히 매핑 — tier는 "축하 크기", reason은 "사건 종류"로 분리.
- **안티수치심:** 약한/정크 세트도 T1으로 터지고 최소 intensity(floor 0.18) 보장.

**`detectPr`** — 점진적 과부하(§6.1). Epley `e1RM = weight·(1+reps/30)`로 이전 베스트 초과 시 PR. 맨몸(weight 0)은 reps를 점수로(같은 종목이라 비교 가능). 첫 세트·동점은 PR 아님(넘어서야 PR).

## 자가 수정 (테스트가 커밋 전에 잡음)

anti-shame floor(0.18)를 T1 base intensity(0.22) **아래**로 뒀더니 floor가 무의미 — 약한 세트가 이미 0.22를 받아 floor가 절대 안 걸림. 테스트 `intensity===0.18`이 0.22로 실패. 의도는 "T1 최소 = anti-shame floor"이므로 **T1 base를 floor(0.18)와 일치**시켜 floor가 실제 하한이 되게 수정. (커밋 전 jest가 잡은 설계 정합성 이슈 — 외부 에러 아님이라 troubleshooting.md엔 안 올림.)
