## 문제

새 사진형 스포츠웨어 아바타는 사진 선택과 생성을 분리했지만, Power 화면의 구형 Evolution은 사진 선택 직후 업로드를 시작했다. 신규 화면의 동의 스위치만 안전하게 만들어서는 같은 앱 안의 기존 경로가 계약을 우회할 수 있었다.

또한 생성 프롬프트에 정면·후면, 불투명 스포츠웨어, 오리지널 IP를 명시하는 것만으로 출력 형식을 보장할 수 없었다. 모델이 정사각형이나 손상된 이미지를 반환해도 기존 응답 검사는 base64 문자열과 MIME 선언만 확인했다.

## 서버 계약

- `/evolve`는 410을 반환하는 tombstone으로 바꿨다. 구형 클라이언트 요청을 다른 parser로 흘려보내지 않는다.
- `/body-avatar`는 `adultConfirmed`, `ownershipConfirmed`, `aiConsent`가 모두 문자열 `true`인지 다시 확인한다.
- 의상은 민소매+쇼츠, 기능성 상의+쇼츠, 컴프레션 세트의 고정 화이트리스트만 허용한다. 자유 프롬프트는 받지 않는다.
- 입력은 JPEG/PNG/WebP의 MIME, magic signature, 5MiB 크기를 검사한다.
- 출력은 base64를 실제 디코딩한 뒤 MIME signature, 4:5 비율, 최소 치수, 최대 픽셀 수, 12MiB 크기를 검사한다.
- Gemini image 요청의 `generationConfig.responseFormat.image.aspectRatio`를 `4:5`로 지정한다. 이 필드는 현재 Google 공식 Generate Content 규격에 있는 값이다.

Worker는 이미지를 저장하지 않고 요청 동안 전달만 한다. 앱은 원본과 결과를 로컬에 보관하며, 신규 body-avatar 파일뿐 아니라 구형 Evolution 원본·결과도 같은 삭제 동작으로 지운다.

## 검증

- `WRANGLER_LOG_PATH=/tmp/reploom-wrangler.log npx wrangler deploy --dry-run`: exit 0, 실제 배포 없음.
- 로컬 handler 직접 호출: `/evolve` 410, 필수 동의가 없는 `/body-avatar` 400.
- 앱 전체 Jest 29 suites / 246 tests, strict TypeScript, lint 통과.
- 개인정보 정책의 로컬 선택, Generate 시 전송, Google Gemini 처리, 로컬 원본·결과 삭제 문구를 앱 문서와 공개 HTML에 함께 반영했다.

## 남은 배포 게이트

실제 Gemini 응답 품질과 배포된 Worker의 새 계약은 아직 확인하지 않았다. 현재 앱의 4+ 초안과 사진 생성의 18+ 확인 정책도 정합성이 없다. 이 두 항목이 닫히기 전에는 Worker 배포나 TestFlight 출고를 하지 않는다.
