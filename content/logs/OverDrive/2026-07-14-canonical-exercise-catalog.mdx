## 맥락과 목표

앱에는 32개 exercise seed가 있었지만 원격 catalog와 오프라인 bundle이 공유할 versioned payload는 없었다. 데이터 작업은 기존 로그·프로그램 identity를 깨지 않고, 검색 가능한 네 언어 이름과 실제 gym taxonomy를 제공해야 했다. 동시에 설명·이미지·의학 주장·외부 corpus 복사, 사람 검토를 받았다는 주장, Worker/D1 운영 변경은 금지했다.

우선순위는 (1) 기존 32 ID와 display order 1–32 보존, (2) 10개 body region과 일반 장비·movement·cardio coverage, (3) exact raw bytes/checksum과 오프라인 bundle 재현, (4) 출처 범위와 비인간 source check의 정직한 기록, (5) 잘못된 데이터를 실제로 거부하는 validator였다.

## 범위 선택

다음 선택지를 비교했다.

1. 기존 32개를 그대로 bundle한다. 호환은 쉽지만 machine·carry·rotation·swim·stair/elliptical 검색 공백이 남는다.
2. 60–80이라는 숫자에 맞춰 운동을 채운다. 겉보기 크기는 늘지만 중복과 억지 `other` 분류가 생긴다.
3. 공개 운동 corpus를 대량 import한다. 속도는 빠르지만 행별 라이선스와 표현물 복사 위험이 계약에 맞지 않는다.
4. 기존 32개를 고정하고 coverage matrix에서 빠진 일반 운동만 추가한다. 이 방법으로 32개가 추가돼 결과가 64개가 됐다.

4번을 채택했다. 64라는 수를 목표로 고른 것이 아니라, 기존 32개 위에 common free-weight/machine/bodyweight와 carry·rotation·step·swim/cardio 공백을 채운 결과다. 우연히 AI candidate projection 상한 안에 전체 snapshot이 들어가는 장점도 있다.

## 산출물과 출처 경계

Snapshot은 53 strength와 11 cardio, 네 locale(`en/ko/es/zh-Hans`)의 독립 작성 display name·gym alias를 담는다. 모든 10개 primary region은 최소 두 운동이 있고, frozen enum 중 `other`를 제외한 equipment 31개와 movement pattern 31개가 실제 ID에 연결된다. `coverage.json`은 각 count 뒤의 ID를 전부 기록해 수치만 맞춘 행을 숨길 수 없게 했다.

Strength taxonomy와 neutral logging defaults는 ACSM 2026 position stand와 AHA 2023 resistance statement를 교차 확인 출처로 기록했다. Cardio activity는 resistance 문헌을 억지 근거로 쓰지 않고 HHS Physical Activity Guidelines 2판만 연결했다. 출처 제목·URL 외 문구는 row에 복사하지 않았다. OpenStax와 wger bulk data도 사용하지 않았다.

모든 row는 `source_checked`/`source_comparison`, role, evidence ID, timestamp를 명시한다. `humanReviewed`는 `false`다. 이 상태는 source 범위를 기계적으로 대조했다는 뜻이지, 네 언어 명칭·분류가 사람 편집 승인을 받았다는 뜻이 아니다.

Publisher-prep은 compact JSON 원문, 한 줄 checksum sidecar, runtime UTF-8가 같은 generated TypeScript 상수, coverage/evidence JSON, dedicated D1용 draft SQL을 결정적으로 만든다. SQL은 `catalog_release.state = draft`만 삽입하고 `catalog_channel`은 갱신하지 않는다. Worker·migration·network·production은 바꾸지 않았다.

## 실패 예측과 전환 조건

- 네 언어 별칭이 문법상 자연스럽지 않을 수 있다. Schema·normalization 검사는 이를 증명하지 못하므로 사람 locale review 전에는 quality verified로 승격하지 않는다.
- 장비나 primary region이 현실과 어긋날 수 있다. 실제 gym 사용에서 오선택이 발견되면 stable ID를 바꾸지 않고 catalog patch version에서 metadata만 수정한다.
- source citation이 row 전체의 사람 검토처럼 보일 수 있다. validator가 `human_reviewed`를 고의 주입하면 실패하고, evidence artifact에도 `humanReviewed: false`를 유지한다.
- 생성 파일이 source와 어긋날 수 있다. `catalog:validate`는 재생성 결과, raw bytes, sidecar, TypeScript runtime 값, coverage를 byte-for-byte 비교한다.

Locale별 사람 검토 증거가 생기면 해당 workflow를 별도 계약으로 추가한다. 실제 zero-result/오선택 근거가 반복되면 alias 또는 taxonomy를 patch version으로 수정한다. 64개 밖의 운동은 숫자 확대가 아니라 새로운 equipment/region/movement coverage 또는 반복 검색 실패가 있을 때만 추가한다.

## 검증 수준

- 기능 검증: `npm run catalog:validate`가 deterministic check와 8개 corruption alarm test를 통과했다. Legacy ID rename, 거짓 human review, region overlap, locale 누락, cardio source 오연결, equipment coverage 손실, stale checksum을 각각 실제로 거부했다.
- 품질 검증: `npm run typecheck`, `npm run lint`, `npm test -- --runInBand`가 통과했다. Jest는 55 suites, 369 tests였다. In-memory SQLite에 D1 draft를 적용해 64 exercise, 256 localization, 256 alias, 117 source, foreign-key error 0, channel update 0을 확인했다. Raw JSON은 103,930 bytes이고 SHA-256은 `b4cacecdeeff7e0c7260070fe1d662454a0d214904cc36c4a269ede542e78bde`였다.
- 제품/워크플로 검증: 미검증이다. 앱 cache/search가 아직 이 bundle을 소비하지 않고, 실제 gym 검색과 locale 사람 검토도 수행하지 않았다.

구현 커밋: `8f0e08cdb93b7fad90ae6bf0af9d197e2edf1987`.

되돌리려면 위 커밋과 이 로그 커밋을 revert한다. 운영 Worker·D1·사용자 데이터는 변경하지 않았으므로 git 밖 롤백은 없다. 통합 후 데이터 문제가 생기면 원격 activation을 멈추고 bundled seed fallback을 유지한 채 patch snapshot을 다시 생성한다.
