클라이언트와 Worker는 교정된 64행 카탈로그를 공통 기준선으로 쓰지만 서로 다른 브랜치에서 병렬로 진행됐다. 클라이언트 계보는 Coach selection metadata, reps capability gate, locale/English 검색 fallback, normalized cache, foreground logging과의 SQLite 경합 완화, frozen/ad-hoc fallback을 구현했다. 통합 브랜치는 같은 데이터의 D1 exact readback, generation-CAS publish, production channel을 구현했다.

`codex/catalog-client`를 `codex/usability-cockpit`에 no-fast-forward로 병합했다. 코드 파일은 자동 통합됐고 append-only `docs/troubleshooting.md`만 충돌했다. 한쪽 기록을 버리지 않고 data integration, guarded publishing, remote output parsing, client logging safety 항목을 모두 유지했다.

merge HEAD에서 strict TypeScript와 Expo lint를 다시 실행했다. 전체 Jest 64 suites / 457 tests와 catalog validator 39/39도 통과했다. 정본은 64행, 66,654 bytes, checksum `sha256:43491e64b66fbd16f87325d8e8ea9e5d2325d888b71c700b61b80da19566604a`로 유지됐다. 직전 Worker HEAD의 86/86 및 production D1 publish readback과 함께 코드·데이터·delivery 계보가 한 브랜치에 존재한다.

이는 기능과 정적 품질 통합 검증이다. 실제 Release simulator에서 schema migration, realistic seed, Coach 플랭크 차단, per-side 표시, locale 검색, 원격 cache activation과 foreground 저장 경쟁을 터치로 확인하지 않았으므로 제품·워크플로 완료는 아직 주장하지 않는다.

병합 커밋은 `1561127`이다. 되돌릴 때는 이 merge를 revert해 클라이언트 계보만 제거할 수 있다. production D1과 channel은 이 merge가 직접 변경하지 않았으므로 해당 외부 상태 rollback은 별도다.
