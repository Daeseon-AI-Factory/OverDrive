## 맥락과 제약

`docs/social-v1-phase0-launch-gate.md`는 Social 계약 `1.0.0` 뒤에 작성된
승인 제안이었다. 이후 커밋 `5e11d4e`가 `1.1.0` 정본을 만들면서 제안의
한-dataset 원칙과 실제 사람 경쟁 분리를 채택했지만, 제안했던 `duels` 이름 대신
친구·크루 비교까지 포함하는 `socialCompetition`을 선택했다. 보존기간, moderation
SLO, TypeORM과 정확한 패키지 버전은 정본에서도 승인되지 않았다.

사용자는 문서 amendment 진행과 미병합 문서 통합을 승인했다. 이 승인은 기능 코드,
dependency, migration, 배포, TestFlight, 결제, App Store 상태 변경까지 넓어지지
않는다. 저장소 규칙상 현재 Phase 1에서 Phase 2/4 진입 증거 없이 Social 코드를
열 수도 없다.

## 목표 — 우선순위 순

1. 과거 제안의 근거를 잃지 않는다.
2. `docs/social-v1-contract.md`가 유일한 구현 정본이라는 우선순위를 지킨다.
3. 채택·수정 채택·미승인을 한눈에 구분해 구현자가 숫자나 package를 추측하지 않게 한다.
4. 문서 통합을 Phase 진입이나 public Social GO로 오해하지 않게 한다.

## 검토한 선택지

1. **아무것도 하지 않는다.** 미추적 제안이 worktree에 계속 남아 승인 입력과
   최종 정본의 관계가 Git에 보존되지 않는다.
2. **제안을 원문 그대로 커밋한다.** 기록은 남지만 `duels`,
   `duelChallengesEnabled`, 정확한 보존기간과 package 제안이 현재 구현 명령처럼
   읽혀 `1.1.0`과 충돌할 수 있다.
3. **제안을 삭제한다.** 정본은 단순해지지만 인증·dataset·sync·삭제·moderation
   대안과 실패 시나리오를 잃는다.
4. **결정 기록으로 바꾸고 integration adjudication을 앞에 둔다.** 정본 우선,
   채택 여부, Phase 비권한을 명시하면서 원래 분석은 historical proposal로 보존한다.

4번을 채택했다.

## 수용한 trade-off

문서가 1,200줄로 길고 역사적 `duels` 예시가 남는다. 대신 section 0에서
`socialCompetition`이 정본임을 명시하고 section 11을 non-normative historical
proposal로 표시했다. 구현자는 이 기록이 아니라 `docs/social-v1-contract.md`와
승인된 후속 packet만 소비해야 한다.

## 6개월 뒤 실패했다고 가정한 pre-mortem

1. **역사 예시를 generated contract로 복사한다.** 방어는 문서 상단의 canonical
   authority와 section 11의 non-normative 표기, 후속 API packet의 정본 검증이다.
2. **제안 숫자를 법적 보존기간으로 공개한다.** 방어는 integration 표에서 retention,
   deletion SLO, moderation SLO를 `Not binding`으로 유지하고 별도 classified amendment를
   요구하는 것이다.
3. **문서 승인을 Phase 4 진입으로 해석한다.** 방어는 P0-00을 CLOSED로 유지하고
   Phase 1 acceptance, Phase 2 entry, Phase 4 entry 또는 roadmap amendment를 별도 증거로
   요구하는 것이다.

## 결정을 뒤집는 조건

- 역사 본문이 반복해서 구현 오입력을 만들면 원문을 별도 archive로 옮기고 현재 문서는
  adjudication과 gate ledger만 남긴다.
- 법률·안전·운영 owner가 숫자를 승인하면 정본의 `TBD`를 classified amendment로
  교체하고 이 기록은 해당 커밋을 가리키게 갱신한다.
- canonical roadmap이 명시적으로 바뀌면 P0-00 행과 packet별 phase authority를 함께
  수정한다.

## 성공 측정과 검증

구현 성공은 주장하지 않는다. 문서 커밋은
`77645fdca9950a1e50e189076489211f91bcc6b2`다. 커밋 출력은 한 파일,
1,200 insertions를 기록했다. 커밋 뒤 재검증 출력은 다음과 같았다.

```text
e6ab7c7cf55219bdbec12e67ce092784fd09e29fd78f6e83d2896799b805c7e3  docs/social-v1-phase0-launch-gate.md
code_fences=6
markdown_tables=consistent
```

`git diff --cached --check`는 커밋 전 exit 0이었고 staged path는 문서 하나였다.
Function 검증은 문서가 Git 커밋으로 보존되고 정본·Phase gate 문구가 검색되는
수준이다. Quality 검증은 Markdown 표, code fence, whitespace 정적 검사까지다.
서버·클라이언트·migration·Windows/macOS clean install과 실제 사용자 workflow는
실행하지 않았다.

## 되돌림

이 기록 단위는 구현 상태나 DB를 바꾸지 않는다. 되돌릴 때는 문서 커밋과 이 로그
커밋을 함께 revert한다. 정본 `1.1.0` 커밋은 이 기록과 독립적이므로 자동으로
되돌리지 않는다.
