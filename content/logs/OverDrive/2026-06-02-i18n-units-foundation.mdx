## 왜 기능보다 먼저

빌더: "영어 한글 스페인어 중국어... 다양한 사람들이 쓰게, 기본은 영어. 단위도 kg/파운드, km/마일 구분." i18n은 **기반(substrate)** — 새 기능마다 문자열이 쌓이는데 나중에 소급하면 지옥이라, 코드베이스 작을 때(전부 한글 하드코딩) 갈아엎었다. 단위도 같은 "표시 로컬라이즈" 문제라 한 묶음.

## i18n (워크플로 설계 → 구현)

`overdrive-i18n-foundation` 워크플로(스택검증 + 전체 문자열 추출 + 언어변이 디자인 + es/zh 번역 + 플랜)로 설계.

- **스택**: react-i18next 17 + i18next 26 (순수 JS, New Arch 무리스크). `fallbackLng:'en'`, `compatibilityJSON:'v4'`(Hermes 복수형). 동기 init → 첫 렌더부터 문자열.
- **카탈로그**: `src/i18n/locales/{en,ko,es,zh}.json`, 118+ 문자열. 네임스페이스 tabs/today/power/history/settings/region/grade/exercise(26)/logger/program/cp/... **등급·부위·운동명까지 4개 언어**(오리지널 IP 등급명 로컬라이즈: Ordinary→超凡, Común→Ascendido 등).
- **영속**: `User.locale`(DB, Phase 2 Postgres 동기) + 설정 언어 스위처(en/ko/es/zh) + Boot에서 로케일 적용 + `<I18nextProvider>`.
- **보류**: expo-localization 기기 자동감지는 네이티브라 다음 dev 리빌드(지금은 en 기본 + 수동 전환으로 핫리로드 작동).

## 언어간 디자인

바디맵 % 블록·버튼·탭 라벨이 긴 번역(es ~25%↑)·짧은 CJK에도 안 깨지게 — region 라벨 numberOfLines·flex 레이아웃. CJK는 시스템 폰트가 처리, 숫자(mono)는 언어 중립.

## 단위 (kg/lb · km/mi)

`src/lib/units.ts` — **저장은 항상 canonical**(무게 kg, 거리 m; 전투력도 kg 계산), **표시/입력만 변환**. SetLogger 무게 스텝퍼가 단위 인지(metric 2.5kg / imperial 5lb step), prefill·repeat는 kg 정확값 유지. 히스토리 `formatWeight`, 설정 단위 스위처(기본 metric). 단위 변환 단위테스트 5.
