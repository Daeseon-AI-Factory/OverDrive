## Context

3-에이전트 전체 감사의 1위 갭: **HealthKit/헬스커넥트가 0% 미구현** — `src/`에 헬스 코드가 한 줄도 없고 전투력이 **100% 수동 로깅** 기반이었다. "실제 운동 데이터(헬스킷/헬스커넥트)를 전투력으로 환산"이라는 제품 헤드라인이 코드엔 없던 셈. 사수 항목: §4(헬스 컴플라이언스 — iCloud 저장 금지·광고/마이닝/판매 금지·수집 타입 명시·거짓 데이터 쓰기 금지), §10(dev client 필요). 컴플라이언스 리서치(`docs/compliance/health-data.md`, `privacy-policy-draft.md`)는 2026-06-02에 이미 박제돼 있어 타입·Info.plist 문구·심사 체크리스트는 확보된 상태였다.

## Options considered

1. **`@kingstinct/react-native-healthkit` v14 (nitro 기반)** — 최신, Expo config plugin, 풍부한 TS 타입.
2. **`react-native-health` (classic 네이티브 모듈)** — 널리 쓰이나 구식, New Architecture/RN 0.85/React 19 정합 불확실.
3. **do nothing** — Phase 후순위로 미룸(헤드라인 갭 유지).

Android는 대칭으로 `react-native-health-connect`.

## Chosen + Why (옵션 1)

- 이 프로젝트는 **New Architecture(RN 0.85, React 19, reactCompiler)** 라 nitro 기반 v14가 정합성이 가장 높다.
- **Expo config plugin**이 HealthKit 엔타이틀먼트 + `NSHealthShareUsageDescription`/`NSHealthUpdateUsageDescription`(문구는 compliance 문서 그대로) 자동 적용 → prebuild로 검증됨.
- TS 타입이 촘촘해 **API 오용을 tsc가 잡아줌**(실제로 워크아웃 필터를 `{date:{startDate}}` + `limit` 필수로 tsc가 교정).

## Trade-off accepted

- nitro + healthkit = **네이티브 스택이 깊어짐** → 크래시 리스크(직전 image-manipulator 버전 스큐 크래시 교훈). 그래서 **읽기 코드 쓰기 전에 토대만 빌드+폰 실행으로 먼저 검증**(verify-before-pile-on).
- **Android는 이 맥에 SDK가 없어**(ANDROID_HOME 미설정/sdkmanager 없음) 코드·설정은 짜되 **빌드/실행은 SDK 환경에서**.

## Reversibility

높음. config plugin + `src/features/health/` 모듈로 **격리**돼 있어 제거 시 deps 빼고 prebuild면 끝. 전투력 통합은 **`verifiedRatio`(보너스 only)** 라 떼어내도 점수 산식이 깨지지 않는다(자가보고 기반은 그대로).

## Verified by (이번 세션 실행)

- `@kingstinct/react-native-healthkit@14.0.2` + `react-native-nitro-modules@0.35.9` 설치(peer: react≥19 / RN≥0.79 충족).
- prebuild → HealthKit 엔타이틀먼트 + Info.plist 2문구 적용, **사이닝 팀·`.xcode.env.local` 엔드포인트 보존** 확인.
- `pod-install` → `NitroModules` + `ReactNativeHealthkit` 통합(Podfile.lock).
- `xcodebuild ... -allowProvisioningUpdates` → **BUILD SUCCEEDED**(새 HealthKit capability에 맞춰 프로파일 재발급) → `devicectl` 설치 + 실행 → **프로세스 RUNNING, 크래시 없음**.
- 읽기 서비스 `src/features/health/{health.ts,types.ts}` — `requestAuthorization({toRead})` + `getMostRecentQuantitySample` + `queryWorkoutSamples`로 워크아웃7d·체중·체지방·VO2·안정심박 읽기, 전부 try/catch(실패 시 빈 스냅샷). **tsc 0 / lint 0 / jest 통과.**
- 커밋: `3c64f57`(네이티브 토대) · `bf42c93`(읽기 서비스).

## 통합 지점 (설계대로) & 다음

`CombatPowerInput`에 이미 있던 **`verifiedRatio`(검증 데이터 비율 → trust 보너스)** + `fitnessMarkers`(VO2max) + `recomp`(체성분)이 정확한 꽂이 지점 — **보너스 only, 페널티 절대 없음(§9)**, 더블카운트 없음(자가보고 basket에 곱해지는 multiplier). Phase 1에서 verifiedRatio는 0이었는데(전부 자가보고), HealthKit이 그 0을 탈출시킨다.

남은 일: ① `combatPowerRepo.buildInput`에 health 스냅샷 합류 ② Settings "Apple Health 연동" UI(권한 요청+플래그+재계산) ③ 재빌드 후 폰에서 권한 허용 → CP 변화 실측 ④ Android Health Connect(코드/설정, 빌드는 SDK 환경).

## Update — 연동 화면 불투명 수정 (e9a8c7b)

빌더 피드백: "연동했는데 뭐 어쩌라고? 뭐가 연동된 건데 sync now 동작 안 하고." 원인 두 겹: (1) **iOS는 READ 권한 허용 여부를 앱에 안 알려줌**(프라이버시) → `connected`=물어봄일 뿐. (2) Apple 건강에 최근 운동 데이터가 없으면(애플워치/피트니스 앱 미사용) 읽을 게 0 → verifiedRatio 0 → CP 불변. 게다가 내 Settings UI가 **숫자 하나(workouts)만 + 동기화 피드백 0** 이라 "죽은 것처럼" 보임.

수정(`src/app/(tabs)/settings.tsx`): 연동 시 **실제 읽은 값**(최근7일 운동·체중·체지방·VO2max)을 표기, 데이터 0이면 **"Apple 건강에 최근 데이터 없음 — 애플워치/피트니스 앱 기록 필요"** 안내, Sync 버튼에 **"동기화 중…" 피드백**(busy state). i18n `read`/`empty`/`syncing` 4로케일. tsc 0 / lint 0 / jest 111. 커밋 `e9a8c7b`.

교훈: 연동/동기화처럼 "백그라운드로 뭔가 한" UX는 **읽은 결과를 보여주고 진행 피드백을 줘야** 한다 — 안 그러면 정상 동작도 고장으로 읽힌다(직전 silent-persist 교훈과 동형).

## Update — 쓰기(write-back) A: 운동 → Apple 건강 (ce57560)

빌더: "내 운동한 게 애플에도 연동돼야 하는 거 아닌가." 맞음 — 그동안 READ만이라 OverDrive→Apple 쓰기가 0이었음. **A 구현(실제 데이터만, §4):**
- `requestHealthAuthorization`에 **`toShare`**(HKWorkoutType, bodyMass) 추가 → 쓰기 권한 요청.
- `writeWorkout(start,end)` = `saveWorkoutSample(WorkoutActivityType.traditionalStrengthTraining, [], start, end)` (enum이라 string 아님 — tsc가 잡아 교정), `writeBodyMass(kg)` = `saveQuantitySample('HKQuantityTypeIdentifierBodyMass','kg',...)`.
- **세션 finish 시**(`useForge.finish`) 연동돼 있으면 방금 끝낸 세션을 HKWorkout으로 기록(startedAt~now). **전투력 등 게임 숫자는 절대 안 씀.**
- 체중 쓰기는 설정 스테퍼가 매 틱 발화라 스팸 위험 → **B(인바디 화면)의 명시적 저장**에서 처리하기로(함수만 준비). tsc 0 / lint 0 / jest 111. 커밋 `ce57560`.

다음: **B — 인바디 입력 화면**(체중/체지방/근육량 입력 → Apple 건강 bodyMass/bodyFat/leanBodyMass 쓰기). 그리고 재빌드 후 폰에서 "세션 끝 → Apple 건강에 워크아웃 뜨는지" 실측. ④ Android는 SDK 환경.
