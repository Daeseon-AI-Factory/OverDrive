## 출발점

사용자 피드백은 명확했다. 메뉴 숫자보다 헬스장에서 얼마나 빨리 운동을 찾고 기록하는지가 중요했고, 기존 부위 추천과 검색은 실제 운동 선택에 도움이 되지 않았다. 원하는 상호작용은 목록을 해석하는 것이 아니라 자신의 캐릭터 몸을 직접 누르는 방식이었다.

코드도 같은 문제를 보였다. 바디맵은 여섯 사각형과 고정 운동 ID 목록으로 구성돼 있었고, 사용자의 오늘 프로그램이나 DB 최근 기록이 부위 추천의 1순위가 아니었다.

## 바꾼 구조

- 불투명 민소매·쇼츠를 입은 오리지널 스포츠웨어 캐릭터의 정면·후면을 기본 자산으로 만들었다.
- 가슴, 어깨, 등, 이두, 삼두, 코어, 둔근, 대퇴사두, 햄스트링, 종아리 10부위를 normalized polygon으로 분리했다.
- 좁은 팔과 종아리는 polygon 바깥 22pt까지 가장 가까운 부위로 보정한다. VoiceOver/TalkBack에는 방향과 무관하게 10개 명명 action을 모두 제공한다.
- 추천은 `오늘 프로그램 → 최근 기록 → 부위 카탈로그` 순이다. 미분류 사용자 운동을 근거 없이 임의 부위에 넣지 않고 전체 검색에 남겼다.
- 부위를 누르면 추천 시트가 열리고 운동을 누르면 기존 로거가 열린다. 세션은 추천을 보는 순간이 아니라 실제 기록 저장 때 생성한다.

## 사진형 아바타의 안전 경계

사진 선택은 로컬 복사만 하고 외부 전송을 시작하지 않는다. 18세 이상, 사진 사용 권리, Google AI 처리 동의를 모두 명시적으로 확인해야 생성할 수 있다. 응답은 MIME signature, 실제 디코딩, 바이트 수, 4:5 비율, 픽셀 수를 검사한다.

검사를 통과해도 생성 모델이 정면·후면 배치를 어길 수 있으므로 곧바로 활성화하지 않는다. pending 미리보기에서 사용자가 왼쪽 정면·오른쪽 후면과 머리·발 정렬을 확인한 뒤 `Use`를 눌러야 manifest가 바뀐다. 닫기와 재시도는 pending 파일만 버리고 기존 활성 아바타는 유지한다.

## 통합 중 잡힌 실패 모드

1. 초기 하체 polygon은 종아리 일부를 대퇴사두·햄스트링으로 판정했다. 512×1280 최종 자산의 실제 관절 위치로 다시 보정하고 자산 anchor 회귀 테스트를 추가했다.
2. 몸을 누르는 순간 fire-and-forget 세션을 만들면 추천만 보고 닫아도 빈 세션이 남고, 빠른 저장과 중복 생성 경쟁이 생길 수 있었다. 실제 logger commit 때만 `ensureSession`을 호출하도록 바꿨다.
3. Power 화면의 구형 Evolution은 사진 선택 즉시 전송돼 새 동의 계약을 우회했다. 진입점을 제거했고 Worker 계약에서는 해당 경로를 410으로 퇴역시킨다.
4. 새 사진 선택이 기존 활성 아바타를 먼저 지우는 경로를 발견했다. 새 preview를 명시적으로 활성화할 때까지 기존 atlas와 manifest를 유지하도록 수정했다.

## 남은 판정

기본 스포츠웨어 아바타의 기능과 시뮬레이터 픽셀은 확인했다. 실제 Gemini 생성물의 다양한 체형 정렬, preview→Use/Discard, 실제 헬스장 한손 사용 시간은 아직 미검증이다. 또한 18+ 생성 조건과 현재 4+ 앱 배포 정책의 정합성을 풀기 전에는 사진 생성을 배포하지 않는다.
