## Context

"경쟁력 있냐 / 어떻게" 질문 → 정직한 답: **로거 시장은 포화, 솔로가 기능·데이터·네트워크로 못 이김.** 차별점은 로깅이 아니라 **JUICE 폭발 + 파워판타지 정체성 + 공유되는 히어로 자산.** 이건 feature 싸움이 아니라 feeling/바이럴 싸움이고, **유일한 검증법 = 모르는 사람이 멈칫하는 공유물을 싸게 던져보는 것.** 이게 스펙 §8의 **Phase 0(외부 훅 데모, 그동안 건너뜀)** 바로 그거다. 빌더가 (B) 제품화를 선택 → 공유 자산부터.

## 구현 (커밋 e688bc2)

두 개의 공유 가능한 "히어로 모먼트":
- **EVOLUTION 히어로 공유** (`EvolutionCard.tsx`) — 진화된 이미지를 RN 내장 `Share.share({url, message})`로 공유 시트에 띄움. 캡션에 전투력·등급 훅 + 해시태그(사용자가 자기 멘트 추가). **새 네이티브 의존성 0** → pod install/리빌드 복잡도 회피(`expo-sharing` 대신 built-in 선택; iOS는 file url 이미지 공유 지원).
- **전투력 폭발 온디맨드 재생** (`power.tsx`) — 평소엔 실제 로깅 때만 터지는 T4 슈퍼노바를 **버튼으로 재생** → 모션 클립을 스크린레코딩하기 위함. `useJuice().fire({tier:4,...})`, 쓰기 0(순수 연출).
- i18n 4개국어(evolution.share/shareCaption, power.demoFire).

## 트레이드오프 / 정직한 한계

- **built-in Share 선택:** 얻음=의존성/pod/리빌드 복잡도 0 / 잃음=`expo-sharing`보다 캡션·플랫폼 제어 약함(iOS 기준 충분). 반응 검증되면 그때 정식 공유 카드(브랜드 프레임 합성)로 승급.
- **합성 카드(before/after + 브랜드 프레임)는 안 만듦** — 화면을 못 보는 상태라 blind 합성은 깨질 위험. 우선 robust한 raw 이미지 + 캡션.
- **검증은 빌더 몫** — 나는 대신 못 올리고 바이럴 여부도 못 봄. tsc0/lint0/jest 128 + 빌드까지만. **외부 반응 = 빌더가 3~5곳 던지고 관찰.**
- 브랜드명(Reploom 후보)은 캡션에 하드코딩 안 함(미clearance) — 훅만, 핸들은 빌더가.

## 다음

빌더: 폰에서 ① EVOLUTION 공유 한 번 ② Power 탭 폭발 재생 스크린레코딩 → 틱톡/릴스/레딧에 던져 **"이거 뭐야" 반응 측정.** 반응 있으면 → 합성 공유 카드 + 워터마크 승급. 없으면 → 감정(뽕맛/테마) 더 키우거나 각도 재고.
