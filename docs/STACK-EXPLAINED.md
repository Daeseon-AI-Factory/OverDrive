# OVERDRIVE 기술 스택 — 백지부터 (용어 0개 가정)

> 너(빌더)가 면접/포폴에서 "이거 왜 썼냐" 방어할 수 있게, **모든 용어를 풀어서** 정리. 실제 `package.json` + `worker/`에 깔린 것만 다룬다(추측 X).
>
> 각 항목 표기: **뭐임(비유) → 왜 썼나 → 꼭 필요?/대안 → 트레이드오프(얻은 것 vs 잃은 것)**
> 판정 태그: 【필수】없으면 앱 자체가 안 됨 · 【제품핵심】이 앱의 존재이유(뽕맛) · 【기능용】특정 기능이 요구 · 【품질】프로답게 · 【선택】대안 있음

---

## 0. 한 장으로 보는 큰 그림

앱은 **양파처럼 층(layer)**으로 쌓여 있다. 안쪽일수록 "필수", 바깥쪽일수록 "이 앱이라서 추가한 것".

```
[ 언어 ]      TypeScript ............ 코드를 쓰는 말
[ 뼈대 ]      React → React Native → Expo ... 화면을 만들고 진짜 앱으로
[ 길찾기 ]    expo-router ........... 화면 간 이동
[ 기억 ]      zustand + SQLite ...... 데이터를 들고 있고/저장
[ 뽕맛 ]      Skia + Reanimated ..... 폭발/애니메이션 (이 앱의 심장)
[ 폰기능 ]    HealthKit, 카메라 등 ... 네이티브 연동
[ 다국어 ]    i18next ............... 4개국어
[ 서버 ]      Cloudflare + AI ....... 무거운 건 클라우드에서
[ 품질 ]      TypeScript검사+테스트+린트
[ 빌드 ]      Hermes/Metro/Xcode .... 코드 → 진짜 폰에 설치되는 앱
```

핵심 직관: **앱의 90%는 "어느 RN 앱이나 쓰는 표준 부품"**이고, **이 앱만의 정체성은 딱 두 군데** — ① 뽕맛(Skia/Reanimated/오디오/햅틱) ② AI 연동(워커+Groq+Gemini). 나머지는 "안 쓰면 오히려 이상한" 기본기다.

## 1. 언어 — TypeScript 【필수】

- **뭐임:** JavaScript(웹/앱의 기본 언어)에 **타입(이 변수는 숫자다, 저건 글자다)**을 붙인 버전. 비유: 맞춤법 검사기 + 자동완성이 빡센 워드.
- **strict 모드:** 그 검사를 **가장 엄격하게**. "혹시 비어있을 수도 있는 값"을 그냥 못 쓰게 막음.
- **왜:** 버그의 70%는 "여기 값이 없을 줄 몰랐어"에서 남. 타입이 **실행 전에** 잡아줌. AI랑 협업할 때도 타입이 "계약서" 역할.
- **대안:** 그냥 JavaScript(타입 없음) → 빠르지만 규모 커지면 지옥. 11k줄에선 TS가 정답.
- **트레이드오프:** 얻음=실행 전 에러 차단, 자동완성, 자기설명적 코드 / 잃음=처음에 타입 쓰는 약간의 귀찮음.
- **면접 한 줄:** "11k줄 솔로 프로젝트라 컴파일 타임에 에러 잡는 strict TS가 필수였다."

## 2. 뼈대 — React → React Native → Expo

이 셋은 **포함관계**다. React(개념) ⊂ React Native(그걸로 앱) ⊂ Expo(그걸 쉽게).

### 2-1. React 【필수】
- **뭐임:** 화면을 **"상태가 바뀌면 화면이 알아서 다시 그려진다"**는 방식으로 만드는 도구. 부품(컴포넌트) 조립식.
- **용어 풀이:**
  - **컴포넌트** = 화면 조각(버튼, 카드). 레고 블록.
  - **상태(state)** = 그 조각이 기억하는 값(예: 카운터 숫자). 바뀌면 화면 자동 갱신.
  - **props** = 부모가 자식에게 넘기는 값(설정값).
  - **훅(hook)** = `useState`, `useEffect` 같은 "기능 끼우는 콘센트". `use~`로 시작.
- **왜:** 사실상 업계 표준. 인력/자료/생태계 압도적.

### 2-2. React Native (RN) 【필수】
- **뭐임:** React로 **진짜 iOS/Android 네이티브 앱**을 만드는 것. 웹페이지를 폰에 욱여넣는 게(=웹뷰) **아님** — 진짜 네이티브 버튼/뷰로 변환됨.
- **왜:** 코드 한 벌로 iOS+Android. 빌더가 JS/React 알면 바로 앱.
- **대안:** Swift(iOS 전용)·Kotlin(안드 전용) = 성능 최고지만 두 벌 짜야 함 / Flutter = 좋지만 Dart라는 다른 언어.
- **트레이드오프:** 얻음=한 벌로 두 OS, 빠른 개발 / 잃음=극한 성능/최신 OS기능은 네이티브보다 한 박자 느림(그래서 뽕맛은 Skia로 따로 챙김).
- **버전:** RN 0.85, **New Architecture** 켬.
  - **New Architecture** = RN 내부 엔진의 신형. JS와 네이티브(폰) 사이 다리(JSI)가 더 빠르고 직접적. 옛날엔 둘 사이에 "통역사"가 있어 느렸는데 신형은 직통.

### 2-3. Expo (SDK 56) 【필수에 가까운 선택】
- **뭐임:** RN을 **쉽게** 쓰게 해주는 **도구상자 + 검증된 라이브러리 세트**. 카메라/파일/햅틱 등을 `expo-OO`로 통일된 API로 제공.
- **왜:** 순수 RN은 네이티브 설정(Xcode/Gradle)이 지옥. Expo가 그걸 대신 관리. 우리 deps의 `expo-*` 20여 개가 다 이 세트.
- **expo-dev-client:** 우리는 **커스텀 네이티브 모듈(HealthKit, Skia)**을 써서, 기본 "Expo Go" 앱으론 못 돌림. 그래서 **"내 전용 Expo Go"를 빌드**한 것 = dev client.
- **트레이드오프:** 얻음=네이티브 설정 지옥 회피, 업데이트 일괄 / 잃음=Expo가 안 싸주는 라이브러리는 직접 네이티브 설정(=우리가 dev client로 푼 지점), SDK 버전에 묶임(그래서 "SDK 56 락").

### 2-4. 곁다리 3총사 (Expo/RN이 내부에서 씀, 너가 직접 거의 안 건드림)
- **Hermes** 【필수】= RN 전용 **자바스크립트 엔진**. 네 JS 코드를 **미리 바이트코드로 컴파일**해 둬서 앱 시작이 빠름. (그래서 폰 번들 `main.jsbundle`이 사람이 못 읽는 바이너리 → `grep -a` 필요했던 그 이유.)
- **Metro** 【필수】= RN **번들러**. 흩어진 수백 개 JS 파일을 하나로 묶고, 개발 중엔 저장하면 바로 반영(핫리로드)되는 서버.
- **React Compiler** 【선택/실험】= 화면 다시 그릴 때 **불필요한 재계산을 자동으로 줄여주는** 최적화기. 원래 손으로 하던 `useMemo` 노가다를 자동화. 우리는 실험 기능으로 켬(그래서 lint에 "compiler 룰"이 있음).

## 3. 길찾기 — expo-router 【필수(네비게이션 중 택1)】
- **뭐임:** **파일 구조 = 화면 구조**인 네비게이션. `src/app/inbody.tsx` 파일을 만들면 자동으로 `/inbody` 화면이 생김.
- **용어:** **라우팅** = "어느 화면 보여줄지 + 화면 간 이동" 관리. **typedRoutes** = 존재하지 않는 화면으로 이동하면 **컴파일 때 에러** 내줌(오타 방지).
- **왜:** 폴더만 만들면 라우트가 생겨서 직관적 + 타입 안전.
- **대안:** React Navigation(코드로 일일이 등록). expo-router가 그 위에 올라탄 더 편한 버전.
- **트레이드오프:** 얻음=직관적/타입안전 / 잃음=파일 규칙을 따라야 함(자유도 약간 ↓).

## 4. 기억(데이터) — zustand + SQLite + async-storage

화면이 데이터를 **"잠깐 들고 있는 것"**과 **"껐다 켜도 남기는 것"**은 다른 문제다.

### 4-1. zustand 【필수(상태관리 중 택1)】
- **뭐임:** 앱 전체가 공유하는 **작은 전역 보관함**. 예: 현재 전투력, 설정값. 어느 화면에서든 꺼내 씀.
- **용어:** **상태관리 라이브러리** = 여러 화면이 같은 데이터를 봐야 할 때 그걸 한 곳에 두고 동기화.
- **왜:** React 기본 state는 "한 컴포넌트 안"만. 여러 화면이 전투력을 같이 보려면 전역 보관함 필요. zustand는 그중 **제일 가볍고 단순**.
- **대안:** Redux(강력하지만 보일러플레이트 많음/무거움), Context(작은 건 OK, 자주 바뀌는 값엔 느림). → **솔로 + 단순함 우선이라 zustand가 정답.**
- **트레이드오프:** 얻음=코드 적고 빠름 / 잃음=Redux 같은 거대 생태계 도구(미들웨어 등)는 덜함(우리 규모엔 불필요).

### 4-2. expo-sqlite 【필수(이 앱 컨셉상)】
- **뭐임:** **폰 안에 들어있는 진짜 데이터베이스(SQL).** 운동기록/전투력/설정 다 여기.
- **왜:** Phase 1이 **"백엔드 없이 오프라인 온디바이스"** 컨셉. 서버 없이도 다 동작해야 함 → 폰 내장 DB.
- **용어:** **마이그레이션** = DB 구조(표)를 버전별로 바꾸는 절차(예: 새 칼럼 추가). **시드(seed)** = 초기 데이터 심기(운동 32종).
- **대안:** AsyncStorage만으로(작은 데이터엔 OK, 관계형 쿼리 안 됨), WatermelonDB/Realm(더 무겁고 큰 규모용). → 구조적 데이터엔 SQLite가 정석.
- **트레이드오프:** 얻음=오프라인 완전동작, SQL 쿼리 파워 / 잃음=마이그레이션 직접 관리(그래서 troubleshooting에 "마이그는 풀 부팅에서만" 함정).

### 4-3. async-storage 【기능용/보조】
- **뭐임:** 아주 작은 **key=value 저장**(언어 설정 같은 단순값). 냉장고 메모지.
- **왜:** SQLite 꺼내기도 뭐한 초소형 값/라이브러리 내부용.
- **트레이드오프:** 단순/빠름 / 구조적 데이터엔 부적합(그건 SQLite 담당).

## 5. 뽕맛 — Skia + Reanimated + 오디오/햅틱 【제품핵심】★

여기가 **이 앱의 존재 이유**다. 스펙 §6·§7: "그래픽은 히어로다." 다른 운동앱과 다른 단 하나.

### 5-1. @shopify/react-native-skia (+ SkSL) 【제품핵심】
- **뭐임:** **고성능 2D 그래픽 엔진.** 구글이 만든 Skia(크롬·안드로이드가 화면 그릴 때 쓰는 그 엔진)를 RN에서 쓰게 한 것.
- **SkSL:** **셰이더 언어.** 셰이더 = **GPU(그래픽카드)에서 픽셀 하나하나를 수학으로 직접 계산**하는 작은 프로그램. 우리 폭발(파티클/충격파/오라)은 이미지가 아니라 **실시간 계산된 빛**이라 IP 걱정 없고 무한 변형 가능.
- **왜:** 일반 RN으론 이런 GPU 폭발 못 만듦. "기록할 때마다 개꼴림"이 제품의 전부 → 전용 그래픽 엔진 필수.
- **대안:** Lottie(미리 만든 애니 재생 — 가볍지만 정해진 것만), 그냥 이미지/GIF(저퀄). → **커스텀 폭발엔 Skia/SkSL밖에 답이 없음.**
- **트레이드오프:** 얻음=무한 커스텀, GPU 풀파워, 에셋 0(다 수학) / 잃음=배우기 어려움(셰이더는 난이도 上), 기기에서만 검증됨(그래서 "테마 폰 확인" 단계가 생김). **← 면접 골드 포인트.**

### 5-2. react-native-reanimated (+ worklets) 【제품핵심】
- **뭐임:** **60fps 애니메이션**을 끊김 없이. 숫자가 튀어오르고, 화면이 흔들리고, 색이 번지는 그 모션.
- **용어:**
  - **worklet** = **UI 스레드**(화면 그리는 전담 일꾼)에서 직접 도는 JS 조각. 보통 JS는 "메인 스레드" 한 명이 다 함 → 무거운 일 하면 화면 버벅. worklet은 **애니메이션을 딴 일꾼한테 시켜** 안 버벅이게 함.
  - **스레드** = 동시에 일하는 일꾼. 메인(로직) / UI(그림) 분리가 핵심.
- **왜:** 스펙 §6 철칙 — **"JUICE는 로깅을 1ms도 막으면 안 된다."** 기록 누르는 순간 폭발이 떠도 저장은 안 느려야 함 → 애니메이션을 UI 스레드로 분리하는 Reanimated가 정확히 그걸 함.
- **대안:** RN 기본 Animated(구형, 종종 메인 스레드 막음). → 비차단 60fps엔 Reanimated가 표준.
- **트레이드오프:** 얻음=버터같은 비차단 모션 / 잃음=worklet 규칙(어떤 코드는 UI스레드에서 못 돎) 학습.

### 5-3. 보조 뽕맛 부품 【제품핵심/기능용】
- **react-native-gesture-handler** = 터치/스와이프/길게누르기 등 **제스처** 정밀 처리. (RN 기본보다 부드럽고 강력.)
- **expo-haptics** = **진동.** 티어별로 약→강 펄스(T4는 트리플 붐). 뽕맛의 촉각 담당.
- **expo-audio** = **소리** 재생/녹음. 효과음(SFX) + 음성로깅 녹음. (소리는 수학으로 만든 WAV 7종.)
- **폰트** `@expo-google-fonts/anton·orbitron` = 콜아웃용 굵은 폰트(Anton) + 숫자용 테크 폰트(Orbitron). 타이포도 뽕맛.
- **expo-image / expo-glass-effect / expo-symbols** = 이미지 표시(캐싱 빠름) / 유리효과 / SF심볼 아이콘. 비주얼 디테일.

## 6. 폰 기능 연동(네이티브) 【기능용】

폰의 진짜 기능(건강데이터·카메라·파일)을 건드리는 다리들.

- **@kingstinct/react-native-healthkit** 【기능용】= **애플 건강(HealthKit) 읽기/쓰기.** 운동/체중/체지방/VO2 읽어서 전투력 신뢰도(verifiedRatio)에 반영, 완료 운동/인바디를 애플헬스에 기록.
  - **react-native-nitro-modules** = 위 라이브러리가 쓰는 **신형 네이티브 연결 기술.** New Architecture에서 JS↔Swift를 빠르고 타입안전하게 잇는 도구. (HealthKit 라이브러리의 부품이라 같이 깔림.)
  - **왜 이 라이브러리:** 애플 공식 API라 직접 Swift로 쓸 수도 있지만, 검증된 RN 래퍼가 시간 절약.
  - **트레이드오프:** 얻음=빠른 연동 / 잃음=iOS 전용(안드는 Health Connect 따로 — 미구현), 컴플라이언스 책임(게임수치 절대 안 씀 §4).
- **expo-image-picker** = 앨범에서 사진 고르기(EVOLUTION/음식). **expo-image-manipulator** = 사진 **리사이즈/압축**(업로드 전 1024px로 줄여 413 에러 방지). **expo-file-system** = 파일 읽기/쓰기/**업로드**(워커로 전송).
- **expo-device / expo-constants / expo-crypto** = 기기정보 / 앱설정값(엔드포인트 등) / 난수·해시.
- **expo-splash-screen / expo-status-bar / expo-system-ui** = 시작 스플래시 / 상단바 색 / 시스템 UI 색. 마감 디테일.
- **expo-linking / expo-web-browser** = 딥링크(앱 URL 열기) / 인앱 브라우저.

> 솔직: 이 중 splash/status/symbols/linking 등은 **Expo가 기본으로 끼워주는 표준 부품**이라 "내가 일부러 골랐다"기보다 "있는 게 정상". 면접에선 HealthKit/이미지 파이프라인만 깊게 말하면 됨.

## 7. 다국어 — i18next + react-i18next 【기능용】
- **뭐임:** 화면 글자를 **언어별로 분리.** `t('settings.title')` 부르면 현재 언어의 문구를 꺼냄. en/ko/es/zh 4개.
- **용어:** **i18n** = "internationalization"(i+18글자+n). 다국어 지원. **보간(interpolation)** = 문구 안에 값 끼우기(`{value}g 단백질`).
- **왜:** 글로벌 출시 염두 + 영어 기본. 하드코딩하면 나중에 지옥 → 처음부터 분리.
- **트레이드오프:** 얻음=언어 추가 쉬움 / 잃음=문자열을 JSON에 따로 관리(약간 번거로움).

## 8. 서버(클라우드) — Cloudflare Worker + D1 + AI 【기능용】

폰에서 못/안 하는 무거운 일(AI, 랭킹 공유)은 **작은 서버**로. **키를 클라이언트에 절대 안 넣기**(§3) 위해서도 서버가 필수.

- **Cloudflare Worker** = **서버 코드를 전세계 엣지에서 도는 작은 함수.** 서버 컴퓨터를 빌리고 관리하는 게 아니라, 함수 하나 올리면 알아서 돎(서버리스). `worker/src/index.js` 425줄.
  - **왜:** ① AI 키를 폰에 넣으면 누구나 훔침 → 서버가 대신 호출(프록시). ② 싸고(거의 무료) 빠름(엣지).
  - **용어:** **서버리스** = 서버 관리 없이 코드만 / **엣지** = 사용자 가까운 전세계 거점 / **프록시** = 폰 대신 AI를 호출해주는 중간 다리.
- **D1** = Cloudflare가 주는 **클라우드 SQLite.** 랭킹(리더보드) 저장.
- **Groq** = **LLM(거대언어모델) 추론 API**, 엄청 빠름. 우리: `/parse`(운동 문장 해석), `/transcribe`(음성→글자, whisper), `/food`(음식 분석).
- **Gemini** = 구글 AI, **이미지 생성** 담당. `/evolve`(EVOLUTION: 내 사진 → 히어로 캐릭터).
  - **트레이드오프:** 얻음=온디바이스로 불가능한 AI / 잃음=네트워크 필요·비용·키 관리(그래서 오프라인 규칙파서 폴백 + 타임아웃 + 키는 `~/.secrets`에서만).

## 9. 품질(프로답게) 【품질】

"돌아간다"와 "믿을 수 있다"는 다르다. 이게 **포폴에서 주니어/시니어를 가르는 부분.**

- **TypeScript 검사 (`tsc --noEmit`)** = 타입 에러를 빌드 전 전수검사.
- **Jest + React Native Testing Library** = **자동 테스트.**
  - **Jest** = 테스트 실행기("이 함수에 2 넣으면 4 나와야 해"를 자동 확인). 우리 **127개.**
  - **RTL** = 화면 컴포넌트를 가짜로 띄워서 "버튼 누르면 이게 보여야 해" 검증.
  - **왜:** 전투력 산식·JUICE 티어판정 같은 **핵심 로직은 틀리면 치명적** → 순수함수로 떼서 테스트. ← 면접에서 "왜 테스트했냐" 좋은 답.
- **ESLint (+ Prettier)** = 코드 **검사기/자동정렬.** 버그 유발 패턴·스타일을 잡음. (`expo lint`로 React Compiler 룰까지.)
- **트레이드오프:** 얻음=리팩터 자신감, 회귀버그 차단, 협업 신뢰 / 잃음=테스트 짜는 시간(하지만 11k줄에선 본전 이상).

## 10. 빌드/배포 — 코드가 진짜 폰 앱이 되기까지 【필수】

- **xcodebuild** = 애플 빌드 도구. 우리 JS+네이티브를 묶어 **진짜 `.app`** 으로. (`expo run:ios`가 프로비저닝을 안 넘겨서, 우리는 직접 xcodebuild 씀.)
- **devicectl** = 애플 CLI. 만든 앱을 **실기기에 설치/실행.**
- **Release vs Debug** = Release는 **JS를 앱 안에 박은 단독실행본**(Metro 서버 불필요), Debug는 개발 중 서버 연결본. 폰 dogfood는 Release.
- **프로비저닝** = "이 앱을 이 폰에 깔아도 된다"는 애플 서명/허가.

## 11. "이거 다 꼭 필요해?" — 솔직한 정리

| 묶음 | 꼭 필요? | 한 줄 |
|---|---|---|
| TS / React / RN / Expo / router / Hermes / Metro | **필수** | 이게 없으면 RN 앱 자체가 성립 안 함 |
| zustand / SQLite | **필수** | 상태 공유 + 오프라인 저장(이 앱 컨셉) |
| **Skia/SkSL · Reanimated · 오디오 · 햅틱** | **제품핵심** | 빼면 그냥 평범한 운동앱. **이게 OverDrive** |
| HealthKit · 이미지·파일 파이프라인 | 기능용 | 특정 기능(헬스/EVOLUTION/음식)이 요구 |
| Cloudflare + Groq + Gemini | 기능용 | AI + 키 보안(서버 없으면 키 노출) |
| i18next | 기능용 | 다국어(글로벌 의도). 국내 전용이면 생략 가능 |
| Jest/RTL · ESLint · tsc strict | 품질 | 빼도 "돌긴" 함. **넣어서 프로처럼 보임** |
| splash/status/symbols/linking 등 잡부품 | 기본제공 | Expo가 끼워주는 표준. "있는 게 정상" |

**결론:** 군더더기는 거의 없음. 진짜 군살 후보는 딱 하나 — **i18n**(혼자 쓸 땐 과할 수 있으나 글로벌 의도면 정당). 나머지는 "RN 표준 + 이 앱의 정체성(뽕맛/AI)"으로 다 설명됨.

## 12. 면접에서 이 앱을 한 문단으로

> "오프라인 우선(온디바이스 SQLite) React Native/Expo 앱입니다. 핵심 차별점은 **GPU 셰이더(SkSL)로 직접 짠 실시간 폭발 연출**과, 그게 **로깅을 한 번도 막지 않도록 Reanimated worklet으로 UI 스레드에 분리**한 점이에요. 전투력 산식·티어 판정 같은 도메인 로직은 순수함수로 떼서 단위테스트(127개) 했고, AI(운동 파싱·음성·이미지 생성)는 **키를 클라이언트에 안 넣으려고 Cloudflare Worker 프록시**로 뺐습니다. TypeScript strict로 전 구간 타입 안전을 깔았고요."

이 한 문단 안 모든 단어를 위에서 다 풀었다. **이걸 네 말로 다시 말할 수 있으면 포폴 준비 끝.**
